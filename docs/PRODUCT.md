# 单商家多门店商业版规划

## 当前阶段：预约闭环演示

已实现用户预约、演示支付、模拟开门、结束使用、保洁、门店权限和 PC / 小程序源码。使用 H2 演示数据库；小程序工具与真机验收待完成。

用户只访问自己的订单；店管理员限定所属门店；商家负责人管理全部门店。PC 当前指标按筛选门店统计演示订单，不代表净营收或支付清算结果。

## 第二阶段：经营功能

门店与包间配置、营业时段、计价套餐、续时冲突检查、取消规则、保洁排班、手机号联系、订单备注、异常使用处理及完整操作日志。

续时需锁定房间并核对后续预约；不能先收款再发现冲突。取消、退款与设备释放分别记录，避免把取消订单等同于退款成功。

## 第三阶段：正式服务接入

- 微信登录：服务端交换身份，手机号授权、角色绑定和会话撤销；禁止客户端任意选择管理员身份。
- 微信支付：服务端创建订单、回调验签、金额与商户核对、重复通知幂等、退款状态和对账。前端支付回调不能直接把订单改为已付款。
- 设备：根据实际供应商接入门锁、灯光、空调或通电模块；记录指令、回执、失败重试和人工处理。真实设备调用不能仅靠数据库事务保证一致性。
- 到时处理：自动结束与设备控制、提醒、设备离线补偿；提前开门和相邻订单之间必须考虑准备间隔与保洁时间。

## 第四阶段：生产交付

生产数据库与迁移、HTTPS、凭据管理、日志脱敏、监控告警、备份恢复、跨端验收、并发测试、微信审核与上线交付文档。

优惠券、会员余额、充值与财务报表另行定义账务模型；当前不实现现金钱包或真实资金托管。

## 验收场景

1. 两名用户同时预约同一时段，只有一单成功。
2. 重复点击、重复支付通知与重复设备请求不造成重复扣款或设备副作用。
3. 用户不能访问他人订单；城南店管理员不能操作湖畔店。
4. 未付款、已取消、超时或不在开门时间窗内，不能开门。
5. 设备无回执时显示失败或处理中，不能宣称已成功开门。
6. 使用结束进入保洁；保洁完成才能恢复使用。
7. 真实退款失败时保留待处理状态与记录，方便后续对账。

第 1、3、4、6 项已有后端测试；第 2 项当前只覆盖预约和演示状态幂等；第 5、7 项待真实服务接入后验收。
